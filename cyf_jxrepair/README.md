# CYF捷修云报修工单管理系统

面向制造企业的设备报修与维修工单管理系统（Web 端），覆盖 **报修提交 → 派单 → 接单 → 完工 → 验收评价 → 归档** 全流程，支持驳回重提、4 种角色权限隔离、统计看板与 AI 智能拓展。

| 项 | 内容 |
|---|---|
| 后端 | Python 3.10+ · FastAPI · SQLAlchemy 2.0 · PyMySQL · PyJWT |
| 前端 | 原生 HTML + CSS + JavaScript（ES Modules，无框架、无构建）· ECharts 5 与字体均为本地文件，断网可用 |
| 数据库 | MySQL 8.0，库名 `cyf_jxrepair` |
| 工单编号 | `CYF` + 日期 + 3 位流水，如 `CYF20261119001` |

## 快速开始

1. 安装 **Python 3.10+** 与 **MySQL 8.0**，确认 MySQL 已启动。
2. Windows 双击 `start.bat`（macOS / Linux 执行 `./start.sh`）。
   - 首次运行会生成 `backend/.env`。**如果 MySQL 的 root 密码不是 `123456`，先改这里的 `DB_PASSWORD`**，再重新运行。
   - 脚本会依次：安装依赖 → 初始化数据库（已存在则跳过）→ 启动服务 → 打开浏览器。
3. 访问
   - 系统首页：<http://127.0.0.1:8000>
   - 接口文档：<http://127.0.0.1:8000/docs>（Swagger UI 已放在本地，断网可用）

需要重置演示数据时执行：`cd backend && python scripts/init_db.py --force`（会清空数据库）。

### AI 智能拓展（题目 4 项全部实现，另加智能派单；默认本地离线运行）

| 功能 | 方法 | 效果 |
|---|---|---|
| ① 故障智能诊断 | 规则推理 + 案例推理（CBR）+ 同义词扩展，noisy-OR 合成置信度 | 24 条口语描述上 Top-1 准确率：仅规则 46% → 混合方案 96% |
| ② 维修知识库检索 | 中文字二元组 + Okapi BM25 | 归档工单自动入库，按匹配度排序并高亮命中词 |
| ③ 工单智能摘要 | 规则抽取结构化字段，可选大模型润色 | 派单页、看板、详情页 |
| ④ 超期工单预警 | 后台定时扫描 + 一键自动派单 / 催办 | 看板顶部警示带 |
| ⑤ 智能派单推荐 | 擅长方向、空闲、同类经验、满意度加权打分 | 每个推荐附带理由 |

完工时维修工确认的故障类别会成为新的诊断案例，系统越用越准。算法、公式、参考文献和评测见 [docs/AI拓展功能说明.md](docs/AI拓展功能说明.md)。

配置 `LLM_API_KEY`（兼容 OpenAI 协议，如 DeepSeek、通义千问）后，诊断和单张摘要会优先调用大模型，失败或无外网时自动回到本地方案。

## 界面设计

参照工厂 MES 终端和纸质维修单设计，不用通用后台模板：

- **状态色遵循 GB 2893 安全色**：黄 = 警告（待派单），蓝 = 指令（待接单、维修中），绿 = 安全（已归档），红 = 禁止（已驳回）。状态用"色块 + 文字"表示，色弱用户也能分辨。
- **工单详情按纸质《设备报修维修单》排版**：带格线的表单、编号、分段标题；已归档或已驳回的工单盖红色印章。
- **超期预警用黄黑警示带**，与车间地面警示线一致。
- 顶部横向导航、直角细线、不用投影；数字和编号使用本地字体 Barlow Condensed 与 IBM Plex Mono（OFL 许可，见 `frontend/assets/fonts/`）。
- 图表配色经过色盲安全校验（蓝 `#1e5aa8` / 橙 `#d4691e`）。

## 架构设计

```
浏览器（原生 JS）                          FastAPI 后端
┌────────────────────────┐   fetch     ┌──────────────────────────────────────────┐
│ pages/*.js  页面逻辑     │ ─────────▶ │ routers/   路由：参数校验、角色守卫          │
│ components/ 分页/弹窗/…  │  JSON /    │    ↓                                     │
│ core/http.js 统一请求    │  multipart │ services/  业务：数据范围、流转、统计、AI     │
│ core/layout.js 菜单守卫  │ ◀───────── │    ├─ workflow.py  工单状态机（唯一规则来源）  │
└────────────────────────┘ {code,      │    ↓                                     │
                            message,    │ models/    SQLAlchemy ORM ── MySQL 8.0     │
                            data}       │ core/      配置·鉴权·统一响应·全局异常       │
                                        └──────────────────────────────────────────┘
```

**关键设计**

1. **状态机集中管理权限**：`services/workflow.py` 用一张 `TRANSITIONS` 表描述"哪个角色、在什么状态、对谁的工单、能做什么"。接口统一调用 `ensure_can()` 拦截越权（员工派单、维修工验收、改动已归档工单等）。详情接口用同一份规则返回 `actions`，前端只渲染后端允许的按钮。
2. **三层权限**：页面层由 `layout.js` 按角色生成菜单并拦截无权页面；接口层由 `require_roles` 守卫；数据层由 `scope_filter` 限定行级范围：员工只看自己的单，维修工只看指派给自己的单，部门管理员只看本部门。越权访问别人的工单返回 404，不暴露工单是否存在。
3. **统一响应与异常**：所有成功与失败（业务异常、参数校验、404、数据库约束、未知异常）都返回 `{code, message, data}`。未知异常只写日志，不把 SQL 细节返回给前端。
4. **数据一致性**：派单等流转操作对工单加行锁（`SELECT … FOR UPDATE`），防止并发重复派单；同一设备有处理中的工单时禁止重复报修；工单编号依靠唯一约束 + 重试保证不重复。
5. **安全**：密码用 PBKDF2 加随机盐哈希，校验时常量时间比较；同一账号 10 分钟内输错 5 次锁定 10 分钟；全部 SQL 走 ORM 参数绑定；上传图片同时校验扩展名、文件头和大小，文件按 UUID 重命名；前端渲染用户内容前一律转义（防 XSS）；登录后跳转地址做白名单校验。

## 常见问题

| 现象 | 处理 |
|---|---|
| `无法连接 MySQL` | 检查 MySQL 服务是否启动，以及 `backend/.env` 中的账号密码 |
| `cryptography package is required` | MySQL 8 默认认证方式需要该依赖：`pip install cryptography` |
| 页面空白、控制台报模块加载错误 | 不要双击打开 html，请通过 `http://127.0.0.1:8000` 访问。如果用 Live Server 单独打开前端，在控制台执行 `localStorage.setItem("cyf_api_base","http://127.0.0.1:8000")` 后刷新 |
| 端口 8000 被占用 | 修改启动脚本中的 `--port` |
